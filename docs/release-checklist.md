# Перед публичным выпуском

## Репозиторий

- Утвердить лицензию на собственный код и добавить `LICENSE`. Документы сторонних компонентов не лицензируют код приложения автоматически.
- Проверить список отслеживаемых файлов и весь Git history, а не только текущее дерево. Не выкладывать `.conf`, ссылки подписок, ключи подписи, сырые логи или скриншоты с персональными данными.
- Сделать `Settings → General → Danger Zone → Change repository visibility → Public`. После открытия можно включить private vulnerability reporting и проверить Secret scanning / Push protection в настройках безопасности GitHub.

## APK

- Сначала оформить лицензии и включить необходимые копии уведомлений и лицензий. Предоставить соответствующий исходный код включённого sing-box для опубликованного бинарника согласно GPLv3, включая необходимые материалы сборки, и проверить остальные зависимости. Не считать ссылку только на главную страницу upstream достаточной.
- Подготовить отдельную релизную подпись. Не коммитить keystore, пароли или приватные ключи. Проверить пакет, версию, ABI, подпись и SHA-256 релизного файла. Если приложение уже установлено с другой подписью, Android не примет обычное обновление поверх него; не предлагать удаление без предупреждения о потере локальных данных.
- Проверить на Android: прямой путь, WireGuard через VLESS/XUDP и HY2, домашний внешний IP, исключения, смену Wi‑Fi/мобильной сети, отсутствие прямого выхода у не исключённых приложений при потере промежуточной ноды. Не обещать Always-on или совместимость со всеми операторами.
- Приложить к GitHub Release APK, контрольную сумму, инструкцию и материалы, необходимые для соблюдения лицензий. Не публиковать отладочный APK как стабильный релиз.
